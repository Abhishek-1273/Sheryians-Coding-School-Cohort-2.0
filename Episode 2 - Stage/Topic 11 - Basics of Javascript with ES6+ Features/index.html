How to Link JavaScript Files Using script-tag

JavaScript file ko HTML ke sath link karne ke liye hum <script src="script.js"></script> tag use karte hain.

index.html 
<!-- Hamesha </body> closing tag se theek pehle link karein -->
<script src="script.js"></script>
</body>
Rule: Script tag ko hamesha </body> ke end me kyun rakhte hain?
Kyunki browser code ko top to bottom line-by-line read karta hai. Agar hum script ko head me bina defer ke rakh denge, toh JS pehle execute ho jayegi jabki HTML elements screen par bane hi nahi honge. Isliye pehle poora HTML DOM load hone dete hain, phir last me script run karte hain.

Variables and Keywords in JavaScript: var, let, const

Variable ek container hota hai jisme hum data store karte hain. JavaScript me variables declare karne ke 3 keywords hain:

Feature var (Legacy ES5) let (Modern ES6) const (Modern ES6)
Scope Function scoped (block {} ke bahar leak ho jata hai) Block scoped (apne {} ke andar locked rehta hai) Block scoped (apne {} ke andar locked rehta hai)
Re-declaration Allowed (same naam dobara — risky) Not allowed (ek naam se ek hi banega) Not allowed (ek naam se ek hi banega)
Re-assignment Allowed (value badal sakte ho) Allowed (value change ho sakti hai) Not allowed (value fixed rahegi)
Hoisting Hoisted, default undefined Hoisted, par TDZ (Dead Zone) me Hoisted, par TDZ (Dead Zone) me
Best Practice Avoid (use mat karo) Use (jab value aage change ho) Default choice (hamesha use karo)
variables-demo.js 
// 1. var - Re-declaration aur Re-assignment dono allowed hain
var a = 10;
var a = 20; // Re-declare ho gaya bina kisi error ke

// 2. let - Re-declare nahi ho sakta, sirf re-assign hota hai
let age = 22;
age = 23;     // Allowed (Value change ho gayi)
// let age = 25; // Error: Identifier 'age' has already been declared

// 3. const - Na re-declare hoga, na value change hogi
const PI = 3.14;
// PI = 3.15; // Error: Assignment to constant variable

Working with Strings & Core String Methods

JavaScript me text data ko String kehte hain. Strings JavaScript me immutable hoti hain (methods original string ko modify nahi karte, hamesha nayi string return karte hain).

String Methods Practice 
let str = "Sheryians Coding School";

// 1. slice(start, end) -> String ka ek hissa cut karke nikalta hai (end index exclusive)
console.log(str.slice(0, 9)); // "Sheryians"

// 2. Template Strings (ES6 Backticks ``) -> Clean string formatting with ${}
let student = "Abhishek";
let course = "Cohort 2.0";
console.log(`Hello ${student}, welcome to ${course}!`);

// 3. split(separator) -> String ko tod kar Array me convert karta hai
console.log(str.split(" ")); // ["Sheryians", "Coding", "School"]

// 4. replace(old, new) -> Pehle matching word ko replace karta hai
console.log(str.replace("Coding", "Development")); // "Sheryians Development School"

// 5. includes(search) -> Check karta hai ki word string me present hai ya nahi (true/false)
console.log(str.includes("Coding")); // true
Interview Question: slice() vs splice() me kya difference hai?
Strings par sirf slice() hota hai, splice() nahi hota!
splice() strictly Arrays ka method hai jo original array ke andar se elements ko add/remove karta hai. Strings immutable hoti hain, isliye strings par splice() method exist hi nahi karta.

What are Statements and Semicolons in JS?

JavaScript me likhi gayi har complete instruction jo koi action perform karti hai, use Statement kehte hain. Semicolon (;) ek statement ka end mark karta hai.

ASI (Automatic Semicolon Insertion):
JavaScript me agar aap semicolon ; lagana bhool jaate ho, toh browser internally khud semicolon add kar deta hai (ASI). Lekin ek hi line me do statements likhte waqt semicolon lagana mandatory hai: let a = 1; let b = 2; (warna SyntaxError aata hai).

What are Expressions in JS and Difference with Statements

Statement

Action Perform Karta Hai

Poora sentence jo computer ko koi kaam karne ko bolta hai. Ye direct kisi value me evaluate nahi hota.

Expression

Value Produce Karta Hai

Code ka har wo tukda jo execute hokar ek concrete VALUE return karta hai (number, string, boolean).

Expression (Value deta hai) Evaluation Result Statement (Action karta hai)
10 + 20 30 let total = 10 + 20;
"Sheryians" + " Cohort" "Sheryians Cohort" console.log("Hello");
age >= 18 true ya false if (age >= 18) { ... }
One-Line Difference: "An Expression produces a value, while a Statement performs an action."

Primitive vs Relative (Reference) Data Types

Primitive (Call by Value)

Direct Value (Stack Memory)

Immutable hote hain. Memory (Stack) me direct value store hoti hai. Copy karne par naya independent copy banta hai.

number, string, boolean, null, undefined, Symbol, BigInt

Relative / Reference (Call by Reference)

Address / Pointer (Heap Memory)

Inhe Relative types isliye bolte hain kyunki ye actual value store karne ke bajaye Heap memory ke address se relate (point) karte hain.

Array [], Object {}, Function ()

Primitive vs Relative Memory Behavior 
// 1. PRIMITIVE TYPE (Copy by Value):
let x = 5;
let y = x; // y ko x ki nayi copy mili
y = 10;
console.log("x:", x, "y:", y); // x: 5, y: 10 (x bilkul safe hai!)

// 2. RELATIVE / REFERENCE TYPE (Copy by Reference):
let obj1 = { name: "Harsh" };
let obj2 = obj1; // obj2 ko obj1 ka memory address mila
obj2.name = "Sheryians";
console.log("obj1.name:", obj1.name); // "Sheryians" (dono same object ko point kar rahe hain!)

Some Important Values: undefined, null, NaN, Infinity

Value Matlab (Simple Hindi) Typeof Result Example
undefined Variable declare kar diya par abhi tak koi value assign nahi ki (JS ki default value). "undefined" let x; console.log(x);
null Developer ne explicitly bataya hai ki ye variable khali (empty) hai. "object" (JS ka historic bug!) let user = null;

Variable Hoisting in JavaScript & TDZ

Hoisting kya hota hai?
Code run hone se pehle JavaScript engine Memory Creation Phase me saari variable aur function declarations ko scope ke top par hoist (lift) kar deta hai.

Keyword Memory Phase (Hoisting) Declare karne se pehle access kiya toh? Output / Error
var Hoisted + Initialized as undefined Undefined value milti hai (Error nahi aata!) undefined
let Hoisted, par uninitialized (TDZ me locked) Temporal Dead Zone (TDZ) me hone ke kaaran error deta hai ReferenceError
const Hoisted, par uninitialized (TDZ me locked) Temporal Dead Zone (TDZ) me hone ke kaaran error deta hai ReferenceError
hoisting-demo.js 
// 1. var ke sath Hoisting:
console.log("var x before declaration:", x); // Output: undefined
var x = 10;

// 2. let & const ke sath (Temporal Dead Zone):
// console.log(y); // ❌ ReferenceError: Cannot access 'y' before initialization
// ---- TDZ (Temporal Dead Zone) yahan tak chalta hai ----
let y = 20; // Yahan TDZ khatam hua, ab y accessible hai
Crucial Interview Question: Kya let aur const hoist hote hain?
YES! let aur const bhi 100% hoist hote hain. Fark sirf itna hai ki var ko default undefined de diya jata hai, jabki let aur const ko uninitialized chhod diya jata hai. Unke declaration tak ka time period Temporal Dead Zone (TDZ) kehlata hai.

Modern ES6+ Operators (Spread, Rest, ??, ?.)

Operator Syntax Purpose & Real-World Use Key Concept
Spread Operator ...iterable Array ya Object ke elements ko khol kar (unpack/expand) naye array/object me copy karna. Shallow copy banata hai.
Rest Parameter ...args Multiple arguments ko ek single Array me samet (pack) leta hai. Spread kholta hai (unpacks), Rest sametata hai (packs).
Nullish Coalescing a ?? b Fallback tabhi deta hai jab left side strictly null ya undefined ho. 0 aur "" ko valid value manta hai (unlike ||).
Optional Chaining obj?.prop?.sub Nested object properties ko bina crash hue safely access karta hai. Missing property par TypeError ke bajaye undefined deta hai.
ES6+ Operators Demo 
// 1. Spread Operator (...) -> Unpacking
const original = [1, 2, 3];
const expanded = [...original, 4, 5]; // [1, 2, 3, 4, 5]

// 2. Rest Parameter (...) -> Packing
function sumAll(...numbers) {
    return numbers.reduce((acc, curr) => acc + curr, 0);
}
console.log("sumAll:", sumAll(10, 20, 30)); // 60

// 3. Nullish Coalescing (??) vs OR (||)
let score = 0;
console.log("score || 50:", score || 50); // 50 (OR ignores 0!)
console.log("score ?? 50:", score ?? 50); // 0  (Nullish preserves 0!)

// 4. Optional Chaining (?.)
const studentData = { name: "Harsh" };
console.log("Safe access:", studentData?.address?.city); // undefined (No crash!)
